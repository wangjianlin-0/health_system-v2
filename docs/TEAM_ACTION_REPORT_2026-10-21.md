## ADS1292R 接口对齐清单

现有文件可以确认：波形 CSV 有 ECG/呼吸原始列和滤波列，时间戳间隔约 2 ms；Heat CSV 每秒一行并包含心率、呼吸率和多个间期字段。下面的问题需负责人确认后再冻结 API：

1. **硬件模块确认：** `ecg_raw`/`ecg_filtered` 和呼吸列分别是什么物理量、单位与量程？原始 ADC 到物理单位的换算/校准参数是什么？500 Hz 是设备保证还是这份样本的观测值？滤波配置和复位/饱和行为是什么？
2. **信号模块确认：** 解析器是否接受该多列表头，输出列选择和元数据是什么？时间戳是否要校验固定步长、缺失、重复和抖动？Heat 表的 0 值如何表为无效/未产生？
3. **模型模块确认：** `pipeline.analyze` 接收哪列、单位和采样率；设备已滤波信号是否再做服务端滤波；Heat 指标能否作为独立设备测量显示，不能作为模型真值的字段有哪些？
4. **记录模块落地：** 建议 API 在确认后接受一份波形 CSV 和可选/配套的 Heat CSV，生成同一 `capture_id` 下的任务、记录、波形与 `device_metrics`。记录需保留信号来源、列名/处理阶段、采样率、单位、时间范围、解析/处理版本。设备指标和模型预测分开存放并分别显示来源；同一捕获文件对的校验失败应生成可追踪任务错误或在提交前返回明确 4xx，团队需选定一致语义。

Heat CSV 首行多个间期为 0，但这只是结构观察；未确认前不能把 0 替换成测量值，也不能当成正常标签。原始样本不应复制进 Git；使用受控本地测试数据和不含个人路径的字段样例。
