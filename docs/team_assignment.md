# 五人分工、交接与验收

此版替代原先“李运嘉承担全部前后端”的分工。两位软件开发按业务模块同时负责页面与接口，不按前后端切割。所有人对自己的代码、调用样例、异常与测试负责。

| 成员 | 开发范围 | 下一批任务 | 验收边界 |
|---|---|---|---|
| 李运嘉 | 应用公共框架、用户、家属与通知 | 身份过期交互、授权邀请/确认、细分权限、通知状态、家庭页面测试 | 两账号验证授权查看和撤回；未授权不能读取；外部推送未接入时不显示已送达 |
| 王书阁 | 上传/分析/历史页面及接口、数据库与服务框架 | 持久化任务状态、异步执行与重启恢复、历史分页/趋势、导出删除 | 上传到保存再回看可追溯；任务不存在/失败明确表达；跨用户隔离 |
| 刘源 | 设备与采集适配、采集控制模块 | 核实开源设备和实际接口；接收/开始/停止；序号丢帧检测；状态页及接口与软件人员共同对接 | 设备输出与回放使用同一信号结构；采样率/单位可核对；断连不伪造连续数据 |
| 林玄初 | 数据来源、解析、信号算法与验证 | 数据许可/来源说明，WFDB 配套文件解析；正式质量和滤波；R 峰/RR/切分 | 用真实采样率；坏信号原因明确；特征与原记录位置对应；训练/推理处理一致 |
| 唐一可 | 数据标签与患者级划分、训练评价、分析流水线 | 可复现基线；真实预测评价；实现 Classifier；把处理和推理封装到 pipeline | 离线与服务输入输出一致；患者不泄漏；模型未加载不假装成功；版本可追溯 |

## 接口交接

1. 刘源向林玄初/王书阁交付带来源、导联、采样率、单位、时间、序号/缺失标记的标准采集数据。
2. 林玄初提供 `parse_csv`、`process`，后续新增 WFDB/滤波/峰检测，返回质量原因、波形和特征。软件层不另写一套解析。
3. 唐一可维护 `ai_model.pipeline.analyze`：先质量判断，再模型推理；它是软件层唯一分析入口。模型函数在 `inference/factory.py` 适配。
4. 王书阁维护任务/记录服务：调用统一入口、关联用户、保存结果与版本，输出给记录页面。
5. 李运嘉维护身份/授权服务，记录服务每次查询重新核验权限。已撤回权限不能通过手工更换记录 ID 绕过。

## 李运嘉模块当前实现

- 会话登录返回过期时间；前端定时退出，并在 401 或自然过期时显示重新登录提示。
- 家庭共享改为邀请确认流程，未接受前不能读取任何共享记录。
- `records:list` 与 `records:read` 分别控制共享列表和详情，授权人可调整范围。
- 邀请支持接受、拒绝、撤回；撤回后列表和详情权限立即失效。
- 站内通知保留历史并支持未读、已读和忽略状态；页面不宣称短信或外部渠道已送达。
- API 测试覆盖会话过期、邀请状态、细分权限、通知已读、撤回和跨用户隔离。

## 工作量控制

- 王书阁不负责家属和账号全部业务，也不负责代写信号/模型算法。
- 李运嘉不负责所有页面，承担完整家庭业务线与公共应用壳。
- 刘源首版复用成熟采集方案；自研电路板、嵌入式 AI 另行评估，不作为软件联调前置条件。
- 林玄初先完成 Python 链路，C 版本在确认端侧需求后再扩展。
- 唐一可以单导联基线先交付，12 导联、多模型不同时作为首版必须项。
- 联调是所有模块作者共同责任，按模块归属修复，王书阁维护问题清单。

## 共同完成标准

可运行代码 + 最小输入样例 + 预期输出 + 异常语义 + 验证证据 + 已知限制。仅建立目录/页面骨架不能标为已验收。每周以实际投入与剩余风险调整任务，不以文件数衡量工作量。
